04

Core data model

Eight tables carry the whole product; math bodies are stored as markdown and rendered client-side through KaTeX after sanitization.

users — id, email, display_name, level, interests[ ], avatar_url
resources — id, owner, title, category, type, difficulty, file_url, status
channels — id, slug, topic, members_count
messages — id, channel_id, author, body_md, created_at
dm_threads / dm_messages — user_a, user_b · thread_id, body_md
ai_threads / ai_turns — user, context · thread_id, role, content, citations[ ]
moderation_queue — resource_id, reviewer, state, notes, timestamps
badges — user_id, kind, earned_at · embeddings via pgvector

06

Extending the AI

The tutor's knowledge lives in one plain array — KB, near the top of the script (search for the marker [1]). Each entry is a worked derivation in a tiny markup: **Step** blocks, · note lines, $…$ math. Copy the template, drop it in, refresh — the topic shelf, the matching engine, and the topics command all pick it up automatically.

{
  id:'gyro-precession',          // unique id
  f:'Mechanics',                 // field — appears as a shelf chip
  t:'Gyroscope precession',      // short title — appears on the shelf
  keys:['gyroscope','precession','spinning top'],   // how questions find it
  a:`One-line setup with concrete numbers.

     **Step 1 — Name the principle**
     $$\\vec\\tau = \\frac{\\mathrm{d}\\vec L}{\\mathrm{d}t}$$ 
     **Step 2 — Do the algebra, substitute last**
     The result, in $\\Omega_p = mgr/I\\omega$, checked against the numbers.

     ·A teal insight line — any paragraph starting with · becomes a note.
     - bullet lines start with "- " and render as lists.`
}

For open-domain questions beyond the shelf, wire aiSay() to a server-side LLM proxy (see §03, AI layer) and stream chunks into the same formatter — the UI won't know the difference.
